# Iris Garden

A flower shop: storefront and admin in one Next.js app. Payload runs the CMS, the
database and the admin panel; the storefront reads it through Payload's Local API,
so there are no internal HTTP calls between the two halves.

- **Framework** — Next.js 16 (App Router, React 19, Turbopack)
- **CMS + data** — Payload 3 on SQLite
- **Styling** — Tailwind CSS v4, no component library

## Getting started

```bash
npm install
npm run seed     # photos, 15 products, 4 categories, an admin user
npm run dev
```

- Storefront — http://localhost:3000
- Admin — http://localhost:3000/admin (`admin@irisgarden.com` / `changeme123`)

`.env` is created for you on first setup and holds `PAYLOAD_SECRET`,
`DATABASE_URI` and `NEXT_PUBLIC_SITE_URL`. It is gitignored. Generate a fresh
secret before deploying anywhere real.

## Scripts

| Command | What it does |
| --- | --- |
| `npm run dev` | Storefront and admin on :3000 |
| `npm run build` / `npm start` | Production build and server |
| `npm run seed` | Rebuild the demo catalogue (deletes products, categories and media — leaves orders alone) |
| `npm run check` | Assertions over checkout pricing and validation |
| `npm run generate:types` | Regenerate `payload-types.ts` after editing a collection |
| `npm run generate:importmap` | Regenerate the admin import map after adding a custom admin component |
| `npm run lint` | ESLint |

Run `generate:types` after any change to a collection or global — the storefront
is typed against that file.

## Layout

```
app/
  (frontend)/        storefront pages
  (payload)/         admin panel and REST API, generated by Payload
collections/         Products, Categories, Media, Orders, ContactMessages, Users
globals/Settings.ts  delivery fees, contact details, home page hero
components/          storefront UI
lib/                 cart store, Payload client, money and query helpers
scripts/             seed and checks
payload.config.ts    collections, database and admin config
```

## Data model

**Products** carry a price in dollars, one or more images, a category, occasion
tags, an `inStock` flag, and optional sizes. A size is a label plus a price delta
in dollars, so "Large +$28" is stored as `28`, not as a second product.

**Categories** are flat and ordered by an `order` field. Occasions are not a
collection — they are a fixed list in `lib/occasions.ts`, shared by the Payload
field options and the storefront filter chips. Add one there and it appears in
both places.

**Orders** snapshot what was bought: the title, size and unit price at the moment
of purchase. Editing a product later never rewrites an old order.

**Settings** is a global holding the delivery fee, the free-delivery threshold,
delivery zones, contact details and the home page hero.

## Money

Product prices are stored in dollars because that is what admins type. Everything
from the cart onwards is integer cents, so totals cannot drift. The two
conversions live in `lib/money.ts` and nowhere else.

The cart in the browser holds product ids, sizes and quantities. It also caches
titles and prices, but only to render the drawer. When an order is placed,
`lib/order.ts` re-reads every price, every size delta and the delivery fee from
the database and ignores what the browser sent. `npm run check` asserts this,
including that a forged size and an out-of-range quantity are both rejected.

The order confirmation page is gated on an httpOnly cookie set when the order is
created, so order numbers cannot be walked to read someone else's address.

## Before this goes live

- **Photos** — the seed pulls demo images from Unsplash. Replace them with your
  own in the admin before launching.
- **Database** — SQLite is a file on disk. On a platform with an ephemeral
  filesystem, swap `sqliteAdapter` in `payload.config.ts` for
  `@payloadcms/db-postgres`. Collections do not change.
- **Uploads** — media is written to `public/media`, which has the same
  constraint. Serverless hosts need a storage adapter (`@payloadcms/storage-s3`
  or similar).
- **Email** — Payload logs emails to the console until an email adapter is
  configured. Order confirmations are not sent to customers yet.
- **Payments** — orders are cash on delivery and are created with status
  `pending`. A gateway would hook into `placeOrder` in
  `app/(frontend)/checkout/actions.ts`.

## Not built

Customer accounts and order history, discount codes, stock counts (a bouquet is
either available or not), reviews, and multi-language content. Payload's
localization can be switched on later without rewriting the pages.
